# Робота з Docker

У цьому проєкті налаштована підтримка Docker для двох середовищ: **Development** (розробка) та **Production** (продакшн). Docker забезпечує ізоляцію середовища, консистентність роботи додатка незалежно від операційної системи та спрощує розгортання.

## Вимоги
- Встановлений [Docker](https://docs.docker.com/get-docker/)
- Встановлений [Docker Compose](https://docs.docker.com/compose/install/)

## Змінні середовища
Перед запуском контейнерів необхідно створити файл `.env` у корені проєкту. Шаблон файлу знаходиться в `env.example`.

```bash
cp env.example .env
```
Заповніть створений файл `.env` актуальними даними, зокрема ключами для Google OAuth та секретним ключем NextAuth.

Ви також можете передати змінну `PORT` у файлі `.env`, щоб змінити порт, на якому працюватиме додаток (за замовчуванням 3000).

## Development (Середовище розробки)

Файл `Dockerfile.dev` описує образ для розробки. Особливості:
- Базовий образ: `node:24-alpine`
- Попередньо встановлені інструменти: `git`, `mc` (Midnight Commander) та `libc6-compat`.
- Код запускається в режимі розробника (`next dev`).
- Використовується користувач `nextjs` (UID 1001) для уникнення проблем з правами доступу.

Для запуску використовується `docker-compose.dev.yml`. В ньому налаштовано прокидання томів (volumes) таким чином, щоб Next.js міг відстежувати зміни у файлах на вашій локальній машині (Hot Module Replacement) і миттєво оновлювати додаток без перезапуску контейнера.

### Запуск в режимі розробки:

```bash
docker-compose -f docker-compose.dev.yml up --build
```
Додаток буде доступний за адресою [http://localhost:3000](http://localhost:3000) (або на порту, який ви вказали).

## Production (Продакшн)

Файл `Dockerfile.prod` описує оптимізований образ для продакшну, використовуючи **multi-stage build (багатоетапну збірку)**. Особливості:
- **Етап збірки (builder):** Завантажує залежності та збирає Next.js додаток (`npm run build`).
- **Етап виконання (runner):** Створює мінімальний образ на базі `node:24-alpine`, копіюючи лише необхідні файли (з папок `.next/standalone` та `.next/static`).
- Для роботи `standalone` режиму переконайтеся, що у файлі `next.config.ts` вказано `output: "standalone"`.
- Контейнер працює від імені непривілейованого користувача `nextjs`.

Для запуску використовується `docker-compose.prod.yml`. Тут не прокидається локальний код, оскільки додаток вже зібраний всередині образу.

### Запуск в режимі продакшн:

```bash
docker-compose -f docker-compose.prod.yml up --build -d
```
Прапор `-d` запускає контейнер у фоновому режимі.
Додаток буде доступний за адресою [http://localhost:3000](http://localhost:3000).

## Налаштування прав доступу
Обидва Dockerfile налаштовані на запуск процесу від імені непривілейованого користувача (`nextjs` з UID/GID 1001). Це найкраща практика безпеки для Docker-контейнерів.
У `docker-compose.dev.yml` вказано `user: "1001:1001"`, що забезпечує коректну роботу з файлами під час прокидання томів, уникаючи ситуацій, коли локальні файли створюються або змінюються від імені користувача `root`.
